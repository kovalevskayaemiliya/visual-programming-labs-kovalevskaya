## 4. Выполненные flow

### 4.1. Inject → Debug

Inject отправляет сообщение каждые 3 секунды. В Debug видно полное сообщение: `payload`, `topic`, `_msgid`.

---

### 4.2. Function

Функция вычисляет произведение массива `[5, 12, 8, 30, 15]` = **216000** и формирует объект с полями `originalArray`, `product`, `message`, `timestamp`.

---

### 4.3. Switch

Switch направляет сообщения по двум ветвям в зависимости от `msg.payload.product`: если `> 100000` — ветка 1, иначе — ветка 2.

---

### 4.4. Change

Change-нода устанавливает `msg.topic`, `msg.timestamp` и меняет `msg.payload`.

---

### 4.5. Template

Mustache-шаблон формирует текст с полями `name`, `group`, `lab` из входного JSON.

---

### 4.6. HTTP Request

Запрос к публичному API `dogapi.dog` возвращает случайный факт о собаках.

---

### 4.7. MQTT

Публикация и подписка через публичный брокер **HiveMQ** (`broker.hivemq.com:1883`), топик `lab2/Ковалевская/mqtt`. Случайные числа отправляются каждые 4 секунды и возвращаются обратно.

---

### 4.8. GET-эндпоинты

Три HTTP-эндпоинта: `/api/text`, `/api/info`, `/api/items/:id`. Третий поддерживает path-параметр `id` и query-параметр `limit`, а также возвращает 400 и 404 при некорректных данных.

Полное описание — в файле [`api.md`](./api.md).

---

### 4.9. Dashboard

Дашборд с gauge и графиком для эмуляции датчика влажности (30–70%).

---

### 4.10. Telegram-бот

Бот `tvl_lab2_kovalevskaya_bot`, обработка команды `/start` и эхо-ответ на произвольное сообщение.

---

### 4.11. Чтение и запись файла

Запись JSON в файл и чтение после перезапуска Node-RED — данные сохраняются.

---

### 4.12. Контекст

Счётчик в `flow`-контексте: после 3 срабатываний сбрасывается, ветвление через два выхода function-ноды.
